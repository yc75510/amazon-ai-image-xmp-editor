# Amazon `contains-synthetic-performer` research

Research date: 2026-07-29 (Asia/Shanghai)  
Scope: Amazon seller-facing requirement, supporting legal context, and initial search-demand/intent evidence. This note distinguishes Amazon's own policy statements from reporting and search observations.

## Executive conclusion

The requirement is real and newly active. The strongest source is Amazon's July 27, 2026 News_Amazon announcement. It requires a pre-upload XMP keyword for an **image or video that contains a photorealistic person entirely generated by AI**, for Listings and A+ Content in Amazon's worldwide stores. It is not a disclosure requirement for every AI-modified image or every AI-generated asset.

This is a credible short-term search opportunity: the official announcement and prominent coverage are only days old; exact-term searches already return at least two narrowly focused browser tools plus new how-to pages. Demand is likely small in absolute volume but has unusually clear, urgent, transactional intent. Ship a narrowly scoped checker/writer page now, then re-evaluate after 2–4 weeks instead of treating it as evergreen high-volume traffic.

## Official Amazon requirement

### Primary policy announcement

| Item | Verified finding |
| --- | --- |
| Source | [You must now tag AI-generated people in listings and A+ content](https://sellercentral.amazon.com/seller-forums/discussions/t/aa0aee06-aff4-497a-a4b6-9b2ebe06f715) — `News_Amazon` |
| Published | 2026-07-27 20:47:07 UTC (page JSON-LD `datePublished`) |
| Core instruction | Before adding product images containing photorealistic AI-generated people to Listings or A+ Content in worldwide stores, add the specified metadata. |
| Exact keyword/field | Use an IPTC-compatible metadata editor to add `contains-synthetic-performer` to the file's `dc:subject` (XMP) field. Amazon describes this for image and video files. |
| Customer effect | Amazon says it will add an indicator informing customers that the image includes AI-generated people, where applicable. |

Amazon's key wording is: “You must now tag product images that contain **photorealistic AI-generated people** with specific metadata before you add them to your listings and A+ content in any of our worldwide stores.” Its next sentence defines the implementation: add the keyword `contains-synthetic-performer` to `dc:subject (XMP)`.

### Scope and exclusions

The same Amazon announcement says the requirement “only applies” when an image or video contains photorealistic AI-generated people. It explicitly says metadata is **not** needed if the image or video:

- only features real people, even if AI tools altered them;
- only features characters from movies, TV, streaming content, documentaries, video games, or other expressive works (for example poster art or game-cover art);
- features no people; or
- does not feature photorealistic people.

The [Product image guide](https://sellercentral.amazon.fr/help/hub/reference/external/G1881?locale=fr-FR) (Amazon Seller Central help, public France mirror of help ID `G1881`) sharpens the boundary: provide the tag where the image features people “entirely generated by AI (not based on a real person).” It repeats the use of an IPTC-compatible editor and `dc:subject (XMP)`.

Recommended public wording for the tool:

> Amazon currently instructs sellers to add this XMP keyword before uploading Listing or A+ media that contains a fully AI-generated, photorealistic person. It is not required merely because an image was edited with AI or contains a non-photorealistic character.

Do not describe the rule as applying to “all AI images,” “all AI video,” or all synthetic/edited humans. Amazon does not publish a mechanical test for “photorealistic,” nor does it explain every borderline case (for example a cropped person).

### Technical implementation source

[How to tag media that contains an AI-generated person](https://sellercentral.amazon.fr/help/hub/reference/external/GFXHCHYZRGJRBZA5?locale=fr-FR) (Amazon Seller Central help, public France mirror of help ID `GFXHCHYZRGJRBZA5`) is the primary implementation reference. It specifies that the XMP `dc:subject` `rdf:Bag` must include an `rdf:li` whose value is `contains-synthetic-performer`.

Useful implementation details from that guide:

- It points sellers to IPTC-compatible metadata editors.
- For Windows File Explorer it says to use **Tags**, not **Subject**.
- Its ExifTool example appends `-XMP-dc:Subject+=contains-synthetic-performer`.
- It warns that rerunning an append operation can duplicate the tag, so a tool must inspect the existing `dc:subject` values first.
- Validation must inspect explicit `XMP dc:subject`; a generic keyword display alone is not sufficient proof.

For wider technical background, [Adobe’s XMP Specifications](https://developer.adobe.com/xmp/docs/) document the XMP model and how XMP is embedded in common formats. Amazon's own help is the authority for this particular `dc:subject` value.

### Timing and existing media

Amazon's main announcement says “You must now,” but it gives no calendar effective date, old-media remediation deadline, or universal file-format matrix.

An Amazon reply in [this Seller Forums discussion](https://sellercentral.amazon.com/seller-forums/discussions/t/3d99e9b8-96f7-4757-acda-3d1da25a6ee3) states: “Compliance is mandatory going forward for new uploads.” The reply timestamp shown on the page is 2026-07-23 23:10:34 UTC. It describes updating the metadata when a listing is edited as a best practice for older media.

Consequently, the site should say **new uploads require compliance going forward**, should encourage users to update media when re-uploading or editing, and should tell sellers to check their current Seller Central guidance. It should not invent a deadline for inventory already uploaded.

## Legal context (do not overstate the connection)

[New York Senate Bill S8420A](https://www.nysenate.gov/legislation/bills/2025/S8420) is a signed law (Chapter 617, signed December 11, 2025) titled “Relates to requiring advertisements to disclose the use of a synthetic performer.” Its official summary says it requires advertisements to disclose use of a synthetic performer, with a $1,000 civil penalty for a first violation and $5,000 for subsequent violations.

Amazon's announcement refers only to “Recent legislation” and does not name a jurisdiction on that page. News reporting connects Amazon's new seller requirement to New York's law, but that causal link is not stated in the Amazon policy itself. Use the statute only as legal context; do not say Amazon's global requirement is the text of the New York statute or offer legal advice.

This is a volatile search-engine estimate, not search volume. The leading organic results included Amazon's Product image guide and very recent how-to/tool pages.

- Broader queries such as `Amazon AI-generated people image requirement` yield a current news pack and videos published within one to five days. This is a strong freshness signal, not evidence of sustained demand.

### Decision

**Hot-window verdict: yes — active but early and narrow.** The best window is now through the near-term policy-compliance cycle. The official announcement has just given sellers a precise string to search and an upload-time action to complete. The main risk is that demand decays after the first wave or becomes absorbed by existing image-workflow products.

Google Trends was deliberately not used as decisive evidence: a newly introduced, low-volume exact technical string can be below Trends reporting thresholds. The above conclusion instead uses first-party publication timing, fresh independent coverage, fresh videos, current seller questions, competitor emergence, and unambiguous “how do I do this?” intent.

## Product implications from the research

1. A valid checker must parse XMP `dc:subject` as a collection and find an exact `contains-synthetic-performer` item; it should not do a loose byte/text search.
2. A writer must preserve existing `dc:subject` items and create/add the `rdf:li` inside an `rdf:Bag` only when the exact value is absent. It must surface an unsupported/unsafe outcome rather than claim success when it cannot preserve the source structure.
3. After writing, re-read the downloadable bytes and display the verified `dc:subject` values. This supports the seller's own verification duty and prevents a UI-only success claim.
4. The product needs a visible eligibility reminder. The tool cannot reliably decide whether a person is fully AI-generated or photorealistic from metadata alone; that remains the seller's assessment.
5. Claim support only for format/container combinations actually verified end-to-end. Amazon's public guidance does not guarantee browser or OS write support for every image/video type.

## Unresolved questions / wording guardrails

- The official announcement does not enumerate every Listing/A+ placement or every image/video encoding/container. Do not advertise universal support.
- It does not publish a test for “photorealistic,” partial-body cases, or a rule for existing uploaded assets beyond the Amazon reply noted above.
- The public French help mirrors identify the needed help IDs and technical instructions but are locale-labelled. Cite the worldwide claim from the `News_Amazon` announcement, not from those mirrored help pages.
- Amazon calls for an “IPTC-compatible metadata editor” but specifies an XMP `dc:subject` value. Do not describe the target as an EXIF field or silently write only IPTC IIM keywords.
